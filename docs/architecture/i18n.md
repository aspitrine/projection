# Internationalisation

Bibliothèque : [Paraglide JS](https://paraglidejs.com) (compilation des messages en fonctions typées, sans provider React).

- Projet inlang : `apps/web/project.inlang/settings.json` — `baseLocale: "fr"`, seul locale pour l'instant.
- Messages : `apps/web/messages/<locale>.json`.
- Code généré : `apps/web/src/paraglide/` (non versionné). Généré par le plugin Vite en dev/build, et par `bun run i18n:compile` (appelé par `check-types`).
- Stratégie de locale : `baseLocale` uniquement. Ajouter `cookie`, `preferredLanguage` ou `url` le jour où un second locale arrive.

## Utilisation

```tsx
import { m } from "@/paraglide/messages";

<h1>{m.members_title({ organization: organization.name })}</h1>;
```

- **Aucun texte d'interface en dur** dans les composants : tout passe par `m.*()`, y compris les messages de validation (`Schema.isMinLength(8, { message: m.auth_password_too_short() })`) et les `aria-label`.
- Appeler `m.xxx()` au rendu (pas au chargement du module) pour rester correct quand plusieurs locales existeront.
- Exceptions : contenus utilisateur (chants, versets…), logs serveur, pages de spike (`/spike/*`).

## Convention de clés

`<zone>_<élément>[_<précision>]`, en `snake_case` :

| Préfixe                                                   | Zone                                                                                   |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `app_`, `coming_soon`                                     | Transverse                                                                             |
| `nav_`                                                    | Navigation du shell                                                                    |
| `home_`                                                   | Page d'accueil publique                                                                |
| `auth_`, `user_menu_`                                     | Connexion, inscription, menu utilisateur                                               |
| `role_`                                                   | Libellés des rôles                                                                     |
| `org_switcher_`, `onboarding_`, `invitation_`, `members_` | Contexte identity                                                                      |
| `dashboard_`                                              | Tableau de bord                                                                        |
| `<contexte>_`                                             | Un préfixe par bounded context (`songs_`, `bible_`, `projects_`, `outputs_`, `live_`…) |

Paramètres entre accolades : `"Bonjour {name}"`. Pluriels et variantes : syntaxe de [inlang message format](https://inlang.com/m/reootnfj/plugin-inlang-messageFormat).

## Ajouter un locale

1. Ajouter le code dans `locales` de `project.inlang/settings.json`.
2. Créer `messages/<locale>.json` avec toutes les clés.
3. Ajouter une stratégie de détection (`cookie`, `preferredLanguage`) et un sélecteur de langue.
